### Changed

- **SynScan telescope: position, status and `DeviceState` are served from a state snapshot** (AlpacaCore, issue #1247; `synscan_telescope_driver.cpp`): one poll body reads the hand controller every second (slewing flag and RA/Dec each tick, Alt/Az, pier side and tracking mode every fourth) and every getter and `DeviceState` answers from memory, so the first `DeviceState` no longer costs four serial round trips (issue #617) and the 2 s position cache is gone (`test_synscan_telescope_snapshot.cpp`: at 100 ms per handset transaction no getter or `DeviceState` call reaches the handset and each returns under 20 ms). `TimeStamp` is the time of the measurement. `SetTracking` is read back at once, and a poll that sampled before a write cannot overwrite it (`a setter's value is read back at once and a stale poll does not undo it`). Three failed polls in a row latch a link fault (getters throw a `DriverException` "communications compromised" while `Connected` stays true); a fault standing 30 s is a lost link: `Connected` reads false, operations throw `NotConnected` and `DeviceState` is empty with no `TimeStamp` (`past the staleness bound DeviceState is empty with no TimeStamp`). A pointing state that is neither E nor W still reads as `SideOfPier` -1 (pierUnknown) from the snapshot, with no handset transaction (`a pointing state that is neither E nor W reads as pierUnknown, not an error`); `SideOfPier` throws only until the handset has answered `p` once. PulseGuide still asks the handset whether a slew is running, so a slew started on the keypad refuses the pulse at once (`PulseGuide refuses while the handset slews even when the frame is older`), and a status tick that starts as the GOTO landing hunt takes the line makes no handset exchange (`a tick that passed its first hold check makes no exchange once the hunt holds the line`). ConformU not re-run (fake-only validation, no hardware).
