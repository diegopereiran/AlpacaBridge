### Fixed
- **SynScan DeviceState, position, Slewing and SideOfPier reads no longer cost four handset round trips** (AlpacaCore, issue #617; `synscan_telescope_driver.cpp`): on an EQM-35 Pro the first DeviceState read after the 2 s position cache expired took 0.56 s (`z` and `e` ~230 ms each, `p` and `L` ~30 ms), over ConformU's 0.1 s FAST target. A background poller thread now refreshes `L`, `e`, `z` and `p` about once a second without holding the driver lock, and the getters answer from its caches with no serial I/O. Every command (slew, sync, abort, MoveAxis, pulse guide, park, unpark, tracking, site and time writes) raises a yield flag so the poller never starts an exchange while one is running: a command waits for at most the one exchange already on the wire. A poll read that a command invalidated while it was in flight is dropped, not published. After 3 failed poll cycles in a row the link latches as faulted: position, Slewing and SideOfPier reads throw `DriverException` ("SynScan communications compromised: ..."), `Connected` stays true, and the first good cycle clears the latch with no reconnect. The poller is a joinable thread, stopped before disconnect closes the link; a cache that is invalid (before the first poll, or after a slew ends) is still refreshed on demand as before.
