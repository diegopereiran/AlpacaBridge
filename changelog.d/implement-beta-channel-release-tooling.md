### Added (tooling)
- **Beta channel release tooling** (release process, `release.yml`, `scripts/release_tag.py`, `scripts/changelog_fragments.py`, `scripts/check_docs_drift.py`, `docs/beta-channel.md`): a tag `vX.Y.Z-beta.N` now publishes a GitHub pre-release from `docs/releases/X.Y.Z-beta.N.md` with no dated CHANGELOG section, after mapping the tag to the `X.Y.Z~betaN` VERSION spelling (`release_tag.py --self-test` covers the mapping and the Debian order). `changelog_fragments.py` accepts a `~betaN` VERSION for `--bump --version` and `--preview --version`, docs-drift check 4 accepts a beta README badge, `changelog_to_deb.py` matches a beta `VERSION` against the legacy UNRELEASED label of its base version, CI and CodeQL also run on pushes to `stable/**`, and `/bump-release`, `/submit-pr` and `/pr-checker` gain beta, stable-branch and merge-down modes. AlpacaCore and AlpacaHTTP CMake pass `project()` only the numeric part of `VERSION`, so a `~betaN` VERSION configures, and keep the full string in `ALPACACORE_VERSION` and `ALPACAHTTP_VERSION`. The update card writes a beta `X.Y.Z~betaN` in its tag spelling `X.Y.Z-beta.N` when it builds the release-notes and Release page links, so a beta offered by the card shows its notes and links to its pre-release. `release.yml` gains a `workflow_dispatch` dry run that builds the notes for a named tag and publishes nothing; `scripts/check_beta_configure.sh` (run by the `build-test` CI job) configures both trees with a beta `VERSION` and checks the `project()` split; `scripts/release_tag_cases.txt` pins the tag mapping and the card's inverse to one list; `changelog_fragments.py --bump` warns when a beta `VERSION` is bumped off a `stable/` branch. A merge-down PR is opened from a short-lived `merge-down/X.Y` head (never `stable/X.Y` itself, which `delete_branch_on_merge` would delete and update-branch would pollute with `main`), after a ruleset protecting `stable/**` is confirmed; the `falsified-by` job skips such a head. `--release` takes a bare `X.Y.Z` only, so a beta cannot consume the fragments. A beta `.deb` gets a `beta` stanza dated noon UTC on the README badge date (`changelog_to_deb.py --date`, passed by `build_deb.sh`) instead of `UNRELEASED` with the build time, so builds are reproducible. `release.yml` refuses a beta tag whose commit is not on a `stable/X.Y` branch (after a merge down `main` carries the beta `VERSION` too); a stable tag is gated as before by its bare `VERSION` and dated CHANGELOG section. `--bump` and `--preview` read the `VERSION` file beside the changelog as their floor, so both name the same version; an impossible `--date` is refused by both changelog scripts; only `X.Y.Z~betaN` is a beta to `changelog_to_deb.py`; `build_deb.sh` reads the badge date through `check_docs_drift.py --badge-date`; the configure check copies the working tree without the vendor SDKs; the pre-flight `falsified-by` gate skips a `merge-down/` head like CI, and the CI skip also requires a same-repository head and base `main`. No user-visible change until a beta is cut.
