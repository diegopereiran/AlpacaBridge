### Changed

- **OnStep mount replies are read with `util::read_until`** (OnStep wrapper, part of issue #1604, the slice issue #1644 left out): the connected-path `read_response()`, the drain after a blind command and the auto-detect probe's `:GVP#`/`:GVN#` reads no longer poll byte by byte with a 10 ms pacing sleep; they wait in `poll()` for the `#` terminator (or, for an unterminated ack, the `#` or a 100 ms idle gap, whichever comes first), with the same timeouts, bytes and errors as before: when the timeout runs out, the next byte within one read slice (100 ms over serial, 200 ms over TCP) still settles the reply, so a late `#` ends its own reply and a reply that starts after the timeout is still "Timeout waiting for OnStep response"; an unterminated ack still returns what came. A hangup on the serial port still loses the link at once ("OnStep link lost (read failed: <errno text>)", `NotConnected`, decision 0009). Over the TCP test seam a peer that hangs up while a command waits now throws a `DriverException` "OnStep network link lost (hangup): <errno text>" at once instead of timing out after the full reply window; the seam is still never latched as lost. Tests: `OnStep mount - a hangup while a command waits for its reply loses the link`, `OnStep mount - a TCP hangup while a command waits for its reply reads as a hangup`, `OnStep mount - a blind-command drain waits one read slice for a stray ack`, `OnStep mount - a read that does not require the '#' ends at the '#'`, `OnStep mount - a '#' that arrives within one read slice after the timeout ends its own reply` and `OnStep mount - a reply that starts after the timeout is still a timeout` (`AlpacaCore/tests/test_mount_read_until_hangup.cpp`).

### Fixed (docs)

- **The #1274 OnStep changelog entry no longer says OnStepX turns tracking on at the end of every GOTO** (changelog fragment, issue #1274): it does so only on the first GOTO after a home reset or one that starts from home, as `.github/instructions/onstep.instructions.md` says.
